## Contract notes for review

1. **`cleanup` deletes messages only.** SPEC P6-T2.1 also names "finished Jobs of
   the request". Jobs are Kubernetes objects; giving the image a Kubernetes API
   right would add RBAC to a tenant identity. The operator deletes them with
   `kubectl` in the window runbook (§9.5 step 1). Proposed SPEC wording change.
2. **Foreign check includes the run attempt when the Job has `RUN_ATTEMPT`.** A
   stale message of an older attempt of the same request is released, like a
   foreign one, and ends in the DLQ after three receives. Without `RUN_ATTEMPT`
   only tenant and request ID are compared.
3. **`fail-always` releases the message (visibility 0)** after `RECEIVED-<n>`, so
   the three receives of B08 need no 120 s waits. Each receive still counts.
4. **The smoke resume step purges and resends** the same run key instead of
   waiting 120 s; resume depends only on S3 checkpoints.
5. **No 12-digit literal in the tests.** The fake ARN account is built at run
   time (`"1234" * 3`) and the ElasticMQ URL uses `/queue/<name>`, so the
   repository ID scans never see an account-shaped value.
6. **`AWS_REGION` alone does not configure a plain `boto3.client`** (smoke helper
   found it). The worker passes `region_name` from `AWS_REGION` explicitly; on EKS
   the IRSA webhook sets both variables.
