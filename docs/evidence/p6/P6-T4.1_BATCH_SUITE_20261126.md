## Findings while testing

1. **Windows `jq` CRLF.** `jq -r` output with several lines kept `\r` on every line
   but the last, so `report` saw `B01\r` and called every case missing. Both
   scripts now wrap `jq` with `tr -d '\r'` (same class of bug as P5 DRF-71).
2. **Pipe into a shell function dropped objects.** On Windows, `jq | tr` feeding a
   shell function under `lastpipe` sometimes failed with `jq: error: Invalid argument`.
   B11 then saw `allow` (fillers never created), and one B06 run found no resumed
   Pod. Manifests now go to kubectl as a here-string (`kapply`), and JSON read
   from kubectl is captured before `jq`. After the fix, both cases passed.
3. **Stale S3 state is not a false PASS.** A rerun on the same S3Mock bucket gave
   B02 `jobs=0`: the submit Job found attempt 1 already `submitted` and sent nothing
   (T2.1 idempotency). B01 then failed `scaler-not-proven`. On EKS each request gets
   a new bucket; within one window a new run needs a new `runAttempt`.
4. **The B09 extra message ends in the DLQ.** It is foreign to every worker, so it is
   released three times. The runbook purges before the `fail-always` attempt so B08
   reads `dlq=1` for its own message only.
