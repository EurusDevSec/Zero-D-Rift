### A worked number (for the owner's micro-lab)

kind has no cloud provider, so OpenCost uses its default prices: CPU `0.031611` USD per core-hour and RAM `0.004237` USD per GiB-hour. The node has 4 cores and about 5.3 GiB, so 4 × 0.031611 + 5.3 × 0.004237 ≈ **0.149 USD/h**, which matches the metric.

In the allocation for `prometheus-system`, `container_cpu_allocation` = **0.125 core**, while real use (`rate(container_cpu_usage_seconds_total[5m])`) was only **0.0085 core**. 0.125 is exactly the sum of the requests (100m + 5m + 10m + 10m). So OpenCost charges max(request, usage): a namespace pays for the CPU it reserves, even when idle. This is the mechanism behind the thesis claim that oversized requests cost money.

## 5. Defect found: every price was 0

On the first install, the OpenCost log showed:
- `Unsupported provider, falling back to default`, which is expected on kind;
- `Failed to download pricing data: … mkdir /var/configs: permission denied`;
- `No pricing found for key=default, setting values to 0`.

The cause is that the container's root filesystem is read-only, and the chart mounts `/var/configs` only when cloud integration or custom pricing is on. As a result, `node_total_hourly_cost` did not exist.

The fix is a 64Mi `emptyDir` at `/var/configs` (`extraVolumes` plus `exporter.extraVolumeMounts`). After `helm upgrade`, `default.json` appears there and the prices are non-zero. It is still not a persistent volume: the folder dies with the Pod, and the content is re-downloaded at start.

On EKS the provider becomes AWS and the files differ. Whether the same folder is needed there is `UNVERIFIED`, but the `emptyDir` costs nothing either way.

## 6. What kind cannot show (carried to the 29/11 window)

These points come from reading the docs (SPEC §12 S4, read 28/11). The OpenCost AWS page and `pkg/cloud/aws/provider.go` on `develop` were read; the file was read only partly.

- **On-Demand price.** It is pulled without credentials from the public price list `pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/current/<region>/index.json`. This fits D3, because no IAM is needed. The system nodes need egress to it on EKS; check it in the window.
- **Spot price without the Spot data feed (our case, D3).** The code tries `DescribeSpotPriceHistory`, which needs AWS credentials that OpenCost does not have. It then falls back to the **On-Demand** price, and finally to a configured default. So **OpenCost will likely price a Spot node as On-Demand**. That overstates the Spot arm, and is one more reason that AWS Billing, not OpenCost, is the source for H5 (D4, D5). The fallback order comes from a partial read; record what the window shows.
- **Spot detection.** The label `eks.amazonaws.com/capacityType=SPOT` was confirmed in the code. A Karpenter label constant exists, but its exact key was not seen, so `karpenter.sh/capacity-type` is `UNVERIFIED`. Check `kubecost_node_is_spot` for the batch node in the window.
- **Not shown on kind:** real nodes, Karpenter, Spot, AWS prices, egress to the price list, and system-node memory headroom (A4).
