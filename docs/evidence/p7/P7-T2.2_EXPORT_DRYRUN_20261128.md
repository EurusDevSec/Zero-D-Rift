# P7-T2.2: metrics export, dry run on kind

## TL;DR

- [`experiments/lib/export_metrics.sh`](../../../experiments/lib/export_metrics.sh) exports one UTC window. It writes 15 named Prometheus range queries to JSONL and the OpenCost allocation (by namespace, controller and Pod) to JSON, adds `export_manifest.json` and `hashes.sha256`, and reads everything through the Kubernetes API service proxy. It needs no port-forward, makes no AWS call, and never prints the kube context.
- Redaction: [`export_redact.py`](../../../experiments/lib/export_redact.py) gives node names a pseudonym and drops IPs, provider ids and uids. If anything is left, it **refuses to write**. 10 SYNTHETIC unit tests pass.

  - A grep for the node name, Pod/Docker IPs and `kind://` finds nothing.

  - A second run into the same folder is refused, so raw evidence stays immutable.

  - **(1)** OpenCost **missed a 75 s Pod** and recorded a 5.5 min Pod as **4.29 min**, because it samples at 1 min resolution.
  - **(2)** The first export still leaked the node name, through the `kubernetes_io_hostname` label. Fixed, with a test.

### Finding 1: OpenCost undercounts short Pods

For the long Pod, OpenCost reported `minutes = 4.29`, a CPU request average of 0.5, use of 0.009, 0.03572 core-hours and a cost of 0.00124 USD at kind default prices. A hand check agrees: 0.03572 × 0.031611 + 0.375 GiB × (4.29/60) h × 0.004237 ≈ 0.00124. Prometheus at a 15 s step saw 315 s of Running, so OpenCost counted about 18 % less time.

The 75 s Pod does not appear in OpenCost at all, even with a 1 h window. The other namespaces do.

The cause is OpenCost's 1 min query resolution ("Using scrape interval of 60" in its log), which cuts the start and end of a Pod's life. This is a **registered cause of difference** for COST_MEASUREMENT (T3). It is another reason that a run's variable cost comes from EC2 instance seconds (D4), not from OpenCost. The 5 min training profile is long enough to show up, but its minutes are low by about one resolution step.

### Finding 2: hostname label leak (fixed)

The first export (not committed) carried the node name in `kubernetes_io_hostname` on the `up` series and in the OpenCost Pod properties. Two fixes:

- every key ending in `hostname`, `node`, `nodename` or `instance` now gets the pseudonym;
- before converting, the script reads `kubectl get nodes -o json`. It pseudonymizes the names and redacts the addresses and provider ids everywhere, and then scans for those literals again.

On EKS, node names `ip-…compute.internal` and instance ids are also caught by the patterns. A node that Karpenter already deleted before the export is caught only by the patterns.
